## Behaviour that could NOT be replicated
None of the brief's listed behaviours were dropped. One small implementation note:
- The original DOM-script wrapped mobile sidebar + lightbox + services-sheet in a shared `overlayStack` with a per-overlay focus trap. The React version keeps the shared *scroll lock* (via `OverlayContext` + `OverlayProvider`) and the Escape + click-outside + focus-on-open behaviours, but does not re-implement the full focus-trap-plus-inert-root. This matches override #10's "simpler Escape + click-outside + focus-on-open is fine; do NOT build a full focus-trap/overlay-manager system."
- Mobile sidebar nav links handle the scroll-to-section themselves via `scrollIntoView` (after `flushSync` closes the overlay). This was necessary because the OverlayProvider restores the pre-open scroll position on close, which otherwise clobbered the browser's default hash-scroll. The result is identical to the original: menu closes, URL updates to the hash, viewport scrolls to the section.
